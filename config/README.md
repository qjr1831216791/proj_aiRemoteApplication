# 环境配置（config）

> 存放**非敏感**的默认配置文件。真实密钥永不入库；环境变量模板在[仓库根目录 `.env.example`](../.env.example)（与 `.env` 同位，便于 `cp .env.example .env`）。

## 环境划分

| 环境 | 用途 | 配置来源 |
|------|------|----------|
| development | 本地开发 | `.env`（本地，不入库） |
| test | CI / 自动化测试 | CI 变量注入 |
| production | 生产 | 部署平台密钥管理注入 |

## 加载优先级（高 → 低）

1. 环境变量（进程 / CI / 部署平台注入）
2. `.env`（本地覆盖，已被 .gitignore 忽略）
3. `config/` 下的默认配置文件
4. 代码内默认值

## 规则

- **新增环境变量必须同步登记到根目录 `.env.example`**：写清变量名、用途、示例值（真实值留空或用占位符）。
- 密钥、token、连接串中的凭据只走环境变量，不写入 `config/` 下的任何入库文件。
- 配置文件用 kebab-case 命名（如 `logging.example.yaml`）；技术栈确定后补充具体的每环境配置文件。
- 应用启动时应对缺失的必需变量**快速失败**并给出明确报错，而不是带默认值静默运行。
