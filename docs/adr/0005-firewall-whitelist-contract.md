# 0005-firewall-whitelist-contract

- 状态: accepted
- 日期: 2026-09-12
- 关联: specs/010-lan-boundary-hardening/spec.md · specs/010-lan-boundary-hardening/plan.md §3.2/§3.3/§3.6 · specs/002-network-profile/spec.md

## 背景与问题

自 spec 002 起，443（Caddy）与 3001（CloudCLI）的入站放行契约是**网络归类（Profile）一比特闸门**：规则 `CloudCLI LAN HTTPS 443` / `CloudCLI LAN 3001`（Profile=Private、RemoteAddress=Any），"专用网络可达、公用被拦"，并以告警提示用户归类失配。该契约有两个结构性缺陷：

1. **归类不构成安全边界**。Profile 是本机视角的便利标签，随网络变更无声翻转（007 acceptance-manual O1 实录过 443 规则漂移为 Profile=Any 的形态——2026-09-12 复验虽不可复现，但漂移风险类别真实存在过）；"专用网络"里同网段的任何设备都可达 3001 与 443，而 CloudCLI 的 3001 是零认证直通宿主机 shell 的面。
2. **007 组网通道落地后语义冗余**。访问已收敛为组网域名（A=虚拟 IP，公网不可路由），成员经 TUN 到达；物理网络归类不再参与成员可达性判断，告警反而成为误报源（换网即报，与实际可达性无关）。

同时，若把 443 收口做弱（仅限源网段单条件），同网段设备把自身物理网卡附加一个虚拟网段地址（`netsh interface ipv4 add address`）即可伪造源 IP 绕过——spec 010 变更记录 2026-09-12 复审结论。

## 决策

**443/3001 的防火墙契约从「Profile 契约」整体迁移到「白名单双条件契约」**（规则 CRUD 单点收敛于 `lan-guard.ps1`，双目录分发）：

| 规则 | 契约 | 语义 |
|------|------|------|
| `CloudCLI Mesh HTTPS 443`（新，唯一 443 闸门） | 入站 TCP 443，**Profile Any** + `RemoteAddress=<组网网段>` + `InterfaceAlias=<TUN 网卡>` | 到达 Caddy 的每个入站包必须从 TUN 接口进入且源 IP ∈ 虚拟网段；Profile 退出契约（与网络归类彻底无关） |
| `CloudCLI LAN 3001 Exception`（新，默认不存在） | 入站 TCP 3001，**Profile Private** + `RemoteAddress=LocalSubnet`，无接口条件 | 局域网直访降级为显式例外开关，最小暴露面 |
| `CloudCLI LAN HTTPS 443` / `CloudCLI LAN 3001`（旧，退役） | —— | 任何脚本不再创建；存量机经启动横幅/向导「一键收口」（`migrate`，幂等删除 + 白名单就位） |

配套决议：**3001 默认拒绝**（删除旧放行规则回落 Windows 默认，loopback 与 Caddy→3001 本机回环流量不受影响）；**例外开启满 12h 自动回落**（回落需 UAC，拒绝则 30min 重试并如实显示「已到期仍放行」）；**002 的 443 归类告警随 Private 语义整体退役**（needs_alert/告警条删除，网络归类**调整**入口保留——008 先例：承载对象退役，功能随对象消亡）。

## 理由

- **双条件 AND 是防火墙过滤器原生语义，直击伪造源 IP**：伪造包从物理网卡进入即不匹配接口条件（网络层不可达，零应用层改动）；而 TUN 只有持 network_secret 入网才可写入——"不可达"性质由拓扑保证，不依赖任何凭证分发。放弃的备选：仅源网段单条件（alias 可伪造绕过）、应用层认证（爆破面 + 凭证分发成本，违背 spec §2 非目标）、WFP 自研 callout（开发量与风险不成比例）。
- **TUN 接口名运行期解析而非常量**：取证实测接口名 `et_8_1999` 为 wintun 按实例生成（服务重装/驱动升级不保证复用同名），固定名是伪契约；以「持有虚拟 IP 的 IPv4 适配器」为语义锚点在脚本内运行期解析。
- **规则名家族即契约**：443 沿「CloudCLI <域> <端口>」命名，例外名含 `Exception` 与旧名明确区分——"旧规则残留"与"例外开着"两个状态纯函数可判定，迁移与开关状态机不凭空多歧义分支。放弃例外复用旧名 `CloudCLI LAN 3001`（省一个名字，换一个状态机歧义）。

## 后果

- 收益：3001 零认证直访从"默认开"翻转为"默认关 + 显式限时例外"；443 闸门与网络归类解耦，007 O1 式 Profile 漂移风险类别随语义退役而消亡；002 告警链死代码删除。
- 代价（接受）：**接口名漂移 fail-closed**——服务重装重建适配器后规则匹配不到任何流量，成员不可达（零暴露但可用性受损）；由白名单健康自检兜底（60s 轮询，`stale_iface`/`stale_cidr` 横幅 + 一键修复，组网「应用」组合派发天然重建）。
- 代价（接受）：例外回落需 UAC 而工作台常驻普通权限——开启时的风险说明预先告知"回落时将再次请求管理员权限"；拒绝/失败按 30min 重试并如实显示仍放行（回落失败不可静默）。
- 对后续的影响：Profile 从 443/3001 契约中退出，仅剩例外规则的 Private 断言（仅展示与断言用，不参与白名单判定）；白名单健康态（`languard://changed`）成为换网/重装场景的唯一反馈通道——若未来新增入站端口，必须并入 lan-guard.ps1 的契约家族（规则 CRUD 单点，禁止第二创建源）。

## 契约变更

- 防火墙规则家族：`CloudCLI Mesh HTTPS 443` / `CloudCLI LAN 3001 Exception` 为仅有的两个合法规则名；旧名 `CloudCLI LAN HTTPS 443` / `CloudCLI LAN 3001` 仅存在于 lan-guard.ps1 删除清单与 Rust 检测常量（迁移横幅判定），创建逻辑全仓零残留。
- 例外 TTL=12h（`now - since == 12h` 即到期）、健康轮询 60s、lan-guard 退出码 0/1/3（成功·幂等跳过 / 前置不满足 / TUN 未解析休眠不建规则）。
- 002 的 US1（443 归类告警）退役，US2（归类调整入口）保留；退役注记见其 spec 变更记录（2026-09-12 行）。
