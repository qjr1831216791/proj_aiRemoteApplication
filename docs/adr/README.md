# 架构决策记录（ADR）

> 一条影响全局的技术决策一个文件，文件名 `NNNN-<kebab-case 决策名>.md`，编号递增不复用。
> **只记录"改变了默认做法"的决策**——常规实现直接写在对应 spec 的 plan.md 里即可。

## 什么时候写 ADR

- 选择语言 / 框架 / 数据库 / 通信协议等基础技术
- 定下跨模块的架构模式（如前后端分离、事件驱动）
- 推翻此前某条 ADR

## 新建 ADR

复制下方模板为 `NNNN-<决策名>.md`，填写后将链接登记到下方索引。

## 索引

| 编号 | 决策 | 状态 | 日期 |
|------|------|------|------|
| — | （尚无 ADR） | | |

## 模板

```markdown
# NNNN-<决策名>

- 状态: proposed | accepted | superseded by NNNN-xxx
- 日期: YYYY-MM-DD
- 关联: specs/NNN-xxx/plan.md

## 背景与问题
<什么约束/问题迫使我们必须做这个决策>

## 决策
<我们选择什么，用一句话能复述的表述>

## 理由
<为什么选它；放弃了哪些备选、为什么>

## 后果
<正向收益 + 必须接受的代价 + 对后续的影响>
```
