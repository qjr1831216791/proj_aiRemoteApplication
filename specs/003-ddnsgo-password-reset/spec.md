## 1. 背景与问题

ddns-go 管理页账密存于 `ddns-go.yaml` 的 `user:` 段，其中密码为 **bcrypt 哈希**（不可逆），忘记后无法查看、只能重置。ddns-go 官方提供 `-resetPassword <新密码>` 参数，但手动操作需要：停进程 → 带 `-c` 指定配置路径执行重置 → 重启——步骤琐碎且 `-c` 漏带时会改错文件（默认路径 `%USERPROFILE%\.ddns_go_config.yaml`，白改）。

需求方（2026-09-09）："帮我增加这个脚本，APP 上增加这个重置功能"——沉淀为 sprint0 工具脚本 + APP 低频操作入口。

**关键事实**（决定方案形态）：

- 密码是哈希，"查看原密码"物理上不可能（spec 001 决策 2 互证：凭证由 ddns-go 自身体系维护）；
- ddns-go 的 `-resetPassword` 走命令行参数——**密码会短暂出现在该进程的命令行里**（任务管理器可见）。这是 ddns-go 官方接口的固有形态；经**可见交互控制台**输入可确保密码不进 APP 界面、IPC 与任何日志，暴露面收窄到"重置瞬间的进程命令行"。

## 2. 目标与非目标

### 目标（Goals）

- 新增 sprint0 脚本 `reset-ddns-password.ps1`：交互式完成"停 ddns-go → 二次确认输入新密码 → `-resetPassword` → 按生产参数重启 → 端口复核"，全程双语（`-Lang`，跟随系统）。
- APP 低频操作区新增「重置 ddns-go 密码」入口，以**普通可见交互窗**拉起脚本（同 `install-client` 通道，无 UAC）。
- 密码只由用户在控制台键入（不回显），**不出现在 APP 界面、IPC、日志中**。

### 非目标（Non-Goals · 本期明确不做）

- **不做 APP 内密码输入框**：避免密码流经前端状态与 IPC（控制台交互已满足诉求）。
- **不支持改用户名**：用户名为明文，脚本只读展示；确需改名走 ddns-go 管理页（记得旧密码时）或手改 yaml 的 `user.username`。
- **不做密码强度校验**：仅做"非空 + 两次一致"校验，其余交给用户判断。
- **不改 ddns-go 本体与其配置结构**；不动 `dnsconf`（DNS 密钥等）。
- 不做密钥/凭证的可视化（spec 001 决策 2 不变）。

## 3. 用户故事与验收标准

### US1: 作为忘记 ddns-go 密码的用户，我希望跑一个脚本就能安全地重置密码，以便不必研究 ddns-go 参数和配置路径。

- [x] **AC1**: Given ddns-go 正在运行 When 执行重置脚本并按提示输入两次一致的新密码 Then 脚本停止 ddns-go 进程、重置密码、按生产参数（`-c <StackDir>\ddns-go.yaml -l :9876 -f 300`）重启并复核 9876 重新监听；旧密码登录失败、新密码登录成功。
- [x] **AC2**: Given ddns-go 未运行 When 执行脚本 Then 跳过停止步骤直接重置并启动，结果同 AC1。
- [x] **AC3**: When 两次输入不一致或输入为空 Then 脚本拒绝执行重置并明确提示，不改动任何状态。
- [x] **AC4**: When 脚本运行 Then 在输入密码前显示当前用户名（自 `user.username` 读取，明文）。
- [x] **AC5**: Given 重置成功但重启失败（端口未监听）When 脚本收尾 Then 给出失败提示与手动排查指引（含"APP 点启动全部"），不以成功口径结束。
- [x] **AC6**: 脚本为双语：跟随系统显示语言，`-Lang zh|en` 可强制（sprint0 既有约定）。

### US2: 作为 APP 用户，我希望低频操作区一键拉起重置流程，以便不回命令行。

- [x] **AC7**: Given 脚本可用 When 点击「重置 ddns-go 密码」 Then 拉起普通可见控制台窗口执行脚本（无 UAC），窗口在脚本结束后保留、输出完整可读；APP 提示"已派发"。
- [x] **AC8**: Given 脚本目录不可用 When 展示低频操作区 Then 该入口禁用并提示原因（同现有脚本可用性约定）。
- [x] **AC9**: 全程密码不写入 APP 日志、不经过 IPC、不出现在任何界面（输入仅存在于控制台与 ddns-go 重置进程的命令行）。

## 4. 功能需求与边界

- **脚本流程**：定位 `ddns-go.exe` 与 `ddns-go.yaml`（产品内固定 `D:\Software\cloudcli-https\`，与 install-server 等脚本同一约定）→ 展示当前用户名 → 停止运行中的 ddns-go（未运行则跳过）→ 输入并确认新密码（不回显）→ `-resetPassword` 重置（校验退出码）→ 隐藏窗重启 → 轮询 9876 监听（上限 30s）→ 打印结论。
- **重启参数契约**：必须带 `-c` 指向栈目录 yaml，且参数与程序内常量一致（`-l :9876 -f 300`）——防止改错默认路径文件（ddns-go 的 `-c` 缺省陷阱）。
- **进程处理**：停止对运行中实例用进程名匹配结束（ddns-go 为本会话用户进程，无需 UAC）；启动用隐藏窗（避免桌面残留控制台），APP 的探活（端口+路径双口径）与后续停止（按路径匹配）不受启动来源影响。
- **APP 侧**：`ToolKind` 新增 `reset_ddns_password`，通道为普通可见交互窗（`VisibleInteractive`）；打包子集与 manifest 同步（`build.ps1` 的 `ScriptSubset` 增补，哈希自动重算）。
- **异常边界**：ddns-go 进程停止失败（权限/占用）→ 明确报错终止，不继续重置；yaml 缺失 → 报错终止并提示先运行 install-server。

## 5. 约束与假设

- 脚本编码遵循 sprint0 约定：UTF-8（BOM）+ CRLF、`T()` 双语函数、`-Lang` 覆盖（见仓库既有脚本）。
- 脚本契约：新增文件不触碰既有脚本对外行为（spec 001 §4.5 契约不变条款）；`resources/bin` 副本由 `build.ps1` 同步，不手改。
- 密码暴露面声明：接受"重置瞬间 ddns-go 进程命令行含密码"（官方接口形态，窗口期秒级，本机自用场景）；除此之外任何通道不留痕。
- 逻辑类 AC 自动化：APP 侧参数构造/可见性/可用性判定（AC7/AC8 逻辑部分）单测；脚本流程与 GUI 交互为控制台/窗口行为，以手工验收清单覆盖（宪法 §1 窄例外）。
- 假设：使用者为管理员账户但本功能**无需提权**（ddns-go 为用户级进程）；栈目录为默认安装路径。
