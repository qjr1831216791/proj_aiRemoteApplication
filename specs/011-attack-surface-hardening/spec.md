## 1. 背景与问题

2026-09-12 全仓安全审查（[报告](../../docs/research/security-audit-2026-09.md)）结论：需求方要求的性质「密钥不泄露 ⇒ 不可入侵」在 spec 010 收口局域网边界后**仍不成立**——剩余三条不经过密钥的路径：

1. **Tauri 命令面**（实现级）：`run_tool` 的 `domain` 参数无校验裸拼进提权 PowerShell（`scripts.rs:492-497` 透传 + `visible_script_params` 对 extra 参数不包裹）；`stack_dir` 任意路径可作可执行来源，且 exe 已存在时 SHA256 校验被短路（`mesh.rs:820`）；CSP=null 无兜底——构成「前端注入 → 静默 RCE」链。
2. **供应链**：Caddy 下载 URL 只锁插件版本不锁核心版本（每次装机下最新版），仅查 ≥10MB + MZ 头无哈希——下载源被污染时装入即中招。
3. **纵深缺失**：组网边界之后 CloudCLI 零认证直达 shell——任何边界破洞（规则漂移、依赖漏洞）都被放大为完全沦陷。

需求方 2026-09-13 对话逐项拍板：①③确认推进，②确认推进且必须配套「傻瓜式组件升级脚本」；低概率事件（依赖 0day、防火墙人为变更、成员设备沦陷）明确排除。完成后安全性质升级为「密钥不泄露 + 成员设备不沦陷 ⇒ 无路可入」。

## 2. 目标与非目标

### 目标（Goals）

- **P1 工作台命令面硬化**：domain 参数校验拒绝注入、EasyTier 二进制校验去短路、CSP 基线——斩断「前端注入 → RCE」链的三道闸。
- **P2 Caddy 指纹锁定**：构建 URL 固定核心版本 + 下载后 SHA256 校验不符拒装——供应链攻击在装机环节被拦截。
- **P3 443 入口 basic_auth（多账号）**：域名访问增加账号密码一道门——管理员在工作台设置区增删账号/改密，不同成员设备持不同凭证（可单独吊销）；凭证仅 bcrypt 哈希落栈目录 `auth-accounts.json`，Caddyfile 标记段由其再生（不经 .env 与环境变量注入链），明文不落盘、不进 settings/日志/命令行。
- **配套组件升级脚本**：`tools/upgrade-component.ps1` 一条命令完成组件版本升级（版本号/哈希/内置二进制/测试联动），升级不再依赖手工找多处改值。

### 非目标（Non-Goals · 本期明确不做）

- **不动网络层语义**：防火墙规则、例外开关、3001 收口形态均为 spec 010 交付物，本期零改动。
- **不做成员凭证体系**：单一共享 network_secret 的 per-device 化/吊销机制排除（需求方 2026-09-13：设备沦陷属非技术场景）。
- **不动 EasyTier 11010 物理层监听**（spec 010 已裁决维持现状）。
- **不改 CloudCLI 自身**（第三方程序，认证加在 caddy 层）。
- **不做 mTLS / 公网暴露**（维持零公网暴露模型）。
- **basic_auth 不覆盖 localhost:3001 与例外期直访**（本地信任与显式例外语义不变，操作提示已覆盖）。
- **不承接 011 原候选**（WiFi 公用防护、install-client 退役）：另行安排编号。

## 3. 用户故事与验收标准

### US1: 作为宿主机使用者，我希望即使工作台前端被注入恶意内容，也无法借工作台执行任意系统命令，以便前端漏洞不被放大为本机沦陷

- [ ] **AC1**: Given `run_tool`/`save_settings` 链路上的 `domain` 或 `stack_dir` 含 PowerShell 元字符（`;` `'` `"` `` ` `` `$` `(` `)` `|` `&` `<` `>` 等）或非法形态（domain 非主机名、stack_dir 非绝对盘符路径或含引号）When 派发/保存 Then 拒绝并返回可读错误（中文、指明字段与非法类别），不构造命令行、不启动任何进程（自动化单测双字段逐元字符断言——stack_dir 为评审补充的同等注入面，见 §7 变更记录）
- [ ] **AC2**: Given `domain` 为合法 DNS 主机名（ASCII 字母/数字/连字符/点分隔，每段 1~63 字符且不以连字符起止，总长 ≤253）且 `stack_dir` 为合法绝对盘符路径 When 派发 Then 参数正常透传、值参数以 PowerShell 单引号字面量包裹（含空格路径不破形），脚本按原语义执行（自动化单测含多级域名、含空格路径用例）
- [ ] **AC3**: Given 栈目录 mesh 子目录已存在五文件且其中任一内容被篡改 When 应用组网配置（apply）Then SHA256 校验失败、拒绝 apply 并报「疑似被篡改」，不派发服务重启（自动化单测：预置篡改文件）
- [ ] **AC4**: Given CSP 已设置 When 开发态（`tauri dev`）与发布构建分别启动 Then 全功能回归正常（启停、设置、向导、地址区、诊断、低频工具），界面行为与 CSP=null 时无差异（真机手工清单逐项核对）

### US2: 作为宿主机使用者，我希望装机下载的 Caddy 与锁定指纹一致并可傻瓜式升级，以便下载源被污染时装机环节直接拦截、升级时不必手工找多处改值

- [ ] **AC5**: Given install-https.ps1 下载 caddy.exe When 下载完成 Then SHA256 与脚本内置锁定值一致才落位；不符则删除临时文件、报错退出（错误提示指向 `-CaddyZip` 手动兜底），栈目录既有文件不被覆盖（真机构造篡改场景验证）
- [ ] **AC6**: Given 构建请求发起 When 检查下载 URL Then 携带固定核心版本参数——同一工作台版本内重复装机下载的字节与哈希恒定，不再漂移到上游最新版（脚本内版本常量与 URL 断言）
- [ ] **AC7**: Given 开发机运行 `tools/upgrade-component.ps1 -Component caddy|easytier -Version x.y.z` When 脚本完成 Then ①锁定值自动改写（caddy：install-https.ps1 版本+哈希；easytier：consts.rs 五哈希 + resources/bin 二进制替换 + manifest 同步）②相关测试通过 ③输出新旧版本/哈希对照与改动文件清单；全程无需手工编辑任何文件（真机演练一次完整升级）

### US3: 作为成员设备使用者，我希望组网边界之外还有一道密码门，以便即使边界被意外绕过，看板与终端也不会直接暴露

- [ ] **AC8**: Given 管理员已添加多个访问账号 When 成员设备以「无凭证 / 错误凭证」访问 `https://域名` Then 返回 401 要求认证；以各自正确账号密码访问 Then 正常进入看板（不同成员持不同凭证，真机浏览器验证）；Given 某账号被移除 When 该成员发起新请求或断开后重连 Then 401 拒绝（既有长连接在断开前可残留，文案注明必要时重启 caddy 彻底断开）
- [ ] **AC9**: Given 未添加任何访问账号 When HTTPS 栈安装/装机向导运行 Then Caddyfile 标记段为空注释、caddy 正常启动与 validate 通过（三条启动路径——工作台托管/开机自启/菜单直启——均不依赖密码相关环境变量），工作台界面呈现「访问账号」管理入口与引导提示（真机验证）
- [ ] **AC10**: Given 本机 `localhost:3001` 直访 When 访问 Then 不受账号密码影响（本地信任语义不变，自动化/真机各一）
- [ ] **AC11**: Given 管理员经设置区「访问账号」管理界面新增/改密/移除账号 When 完成 Then 账号与 bcrypt 哈希持久化于栈目录 `auth-accounts.json`（仅哈希无明文，栈目录既有 ACL 覆盖），Caddyfile 标记段由该文件**再生**为多账号 basic_auth 块；用户名经字符白名单校验、密码经非空与最小长度校验；密码明文仅在工作台内存瞬时经过，**不落盘、不进 settings/日志/命令行**（含断言测试）；每次写 Caddyfile 前备份、后 `caddy validate` 自检（失败自动回滚），`caddy reload` 零停机生效（caddy 未运行则提示下次启动生效）；存量装机（v0.6.0 及更早，Caddyfile 无标记段）首次管理操作自动定位 site 块插入标记段（真机验证）

## 4. 功能需求与边界

- **校验位置（双闸）**：Rust 侧 `tool_plan` 派发纯函数校验 `domain` 与 `stack_dir`（前端不改——前端被攻破时校验依然生效）；`save_settings`/`normalize_stack_dir` 源头同规格校验（写入即拒）。拼接 sink 处 `visible_script_params` 对**值参数**一律 PowerShell 单引号字面量包裹（内部 `'` 翻倍）——参数名 token（如 `-Update`）不包裹，引号会使 PowerShell 将其绑定为位置实参。
- **校验失败的错误传播**：`run_tool` 返回可读错误字符串（中文），前端 toast 呈现，不弹 UAC。
- **SHA256 去短路的性能口径**：五文件约 20~40MB 哈希读取为毫秒级，apply 频率低，无缓存设计。
- **Caddy 锁定值位置**：install-https.ps1 头部常量区（版本 + SHA256 成对出现），manifest.json 登记 ps1 哈希（既有机制自动覆盖）。**校验严格先于落位**（任何向目标路径的复制之前完成比对）；`-CaddyZip` 手动兜底路径明示「未经哈希锁定校验（人工信任转移）」。
- **访问账号管理**：事实来源为栈目录 `auth-accounts.json`（用户名 + bcrypt 哈希，无明文）；Caddyfile 标记段（install-https.ps1 生成时即带空段）每次账号变更后由该文件再生为多账号 basic_auth 块，标记段缺失时（存量装机）定位 site 块自动插入；bcrypt 哈希由 Rust 命令 spawn 栈目录 `caddy.exe hash-password --algorithm bcrypt` 以 stdin 生成（密码不进命令行）；写前备份、`caddy validate` 自检失败回滚。
- **升级脚本边界**：纯仓库侧开发工具（tools/），不随安装包分发；联网下载失败时给出手动放置路径的引导，不半写锁定值（先下载校验、后改写）；输出官方校验和来源（caddy GitHub release checksums）供人工对照一行——P2 锁定属首次信任（TOFU），首次下载的人工对照是唯一补救。
- **兼容性**：已装机的存量栈目录不受影响——Caddy 指纹锁定只约束新下载（`-Update` 与新装）；basic_auth 未设置密码前行为与现状完全一致。

## 5. 约束与假设

- 遵循 [开发宪法](../../docs/constitution.md)：密钥/密码不进命令行、日志、settings。
- caddyserver.com 按需构建产物的**字节可复现性**与下载 API 的**版本参数支持**是方案 A（下载校验）的假设前提——T4 实施首步以「URL 断言 + 两次独立下载比对」验证；任一不成立则**当次**切换方案 B（caddy.exe 随包内置，EasyTier 同款待遇），不允许带 A 上线后再切，spec 不变、plan 变更记录登记。
- CSP 指令集以 Tauri 2 文档为准（`default-src 'self'` + ipc 源；Tauri 2 编译期自动为其注入脚本补 nonce/hash——官方文档证实），以 dev/build 双回归为验收口径，不为过紧指令牺牲功能；dev HMR 若被拦，经 `devCsp` 加 `ws://localhost:5173` 出口处理，不动生产 csp。
- PowerShell 5.1 运行环境（既有脚本基线）；bcrypt 哈希生成复用栈目录 `caddy.exe hash-password --algorithm bcrypt`（stdin 传入，密码不进命令行；显式指定算法防上游默认值漂移）。
