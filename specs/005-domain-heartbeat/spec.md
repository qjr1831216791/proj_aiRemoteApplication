## 1. 背景与问题

域名访问失效的原因多样且隐蔽（防火墙归类、DNS 记录错写、CGNAT/假公网、隧道断链、caddy/上游挂——2026-09-09 排查实录见 [004 spec §1](../004-tunnel-access/spec.md)），共同点是**服务端用户看不出来哪里挂了**，每次都要人工逐环排查。需求方明确（2026-09-09）："对访问地址增加心跳检测，如果不通要显示出来（比如红色标记）"。

**关键约束（同日实证）**：本机探测 ≠ 外部视角——hairpin NAT / CGNAT 网络下，本机 `curl https://ai.jackqi.cn/` 超时但移动网内手机可访问（004 spec §1、§4「可达性口径」）。心跳检测必须**分层定责**并如实标注口径，不能把"本机路径不通"冒充"外部不可达"，否则制造新的误导。

## 2. 目标与非目标

### 目标（Goals）

- 对工作台地址区（本机/局域网/域名，重点域名）做**周期心跳检测**，结果可视化：不通时**红色醒目标记**，恢复自动消除。
- 失效时**分层定责**：DNS 解析 / 本机组件（caddy、上游）/ 本机全链路 HTTPS，逐层显示通/断，用户能直接看到"断在哪一层"。
- 检测口径如实标注（"本机视角"），并预留外部视角探测的增强位（见开放问题）。

### 非目标（Non-Goals · 本期明确不做）

- **不做告警推送**（邮件/webhook/手机通知）：本期只在界面显示；push 另立。
- **不做历史曲线/可用率统计**：只报当前状态。
- **不做隧道通道本身的重复检测**：frpc 进程状态已由 004 守护覆盖，心跳只测"访问结果"。
- 不改动 004 的通道切换/守护/DNS 指引逻辑（心跳只读其产出的状态做聚合展示，不写）。

## 3. 用户故事与验收标准

### US1: 作为服务端用户，我希望域名地址被周期心跳检测，在不通时以红色标记，以便失效即时可见、不必手动测试。

- [ ] **AC1**: Given 心跳检测开启（默认开）When 域名 HTTPS 探测失败（连续 ≥2 次，防抖）Then 地址区域名行显示红色标记与"最近失败时间"，界面其他区域不受影响。
- [ ] **AC2**: Given 红色标记显示中 When 探测恢复成功 Then 标记自动消失并显示恢复时间。
- [ ] **AC3**: Given 心跳开启 When 每轮检测完成 Then 检测时间与结论（通/断/进行中）在地址区可见，不弹窗打断。

### US2: 作为服务端用户，我希望失效时看到"断在哪一层"，以便直接定位原因而不用逐环排查。

- [ ] **AC4**: Given 域名探测失败 When 展示分层结论 Then 至少区分三层各自的通断：① DNS 解析（是否解析、CNAME 是否对齐——复用 004 检测）；② 本机组件（caddy 443 监听 / 上游 3001——复用现有 probe）；③ 本机全链路 HTTPS（本机视角）。
- [ ] **AC5**: Given 展示分层结论 When 本机全链路失败而 ①② 均正常 Then 明示"本机路径不通（可能为网络形态所致，外部设备可能仍可访问）"——不冒充外部视角结论。

### US3: 作为服务端用户，我希望心跳不影响正常使用，以便检测本身不成为新故障源。

- [ ] **AC6**: Given 心跳运行中 When 网络抖动导致单次失败 Then 不立即标红（连续 ≥2 次防抖），恢复后不留残余告警。
- [ ] **AC7**: Given 设置页 When 用户关闭心跳 Then 不再发起探测（既有红色标记冻结并标注"已停用"），其余功能不受影响。

## 4. 功能需求与边界

- **探测实现**：本机 HTTPS 探测走标准 HTTP 客户端（超时 plan 定，建议 8s），不复用 curl 子进程；DNS 层复用 004 `check_dns_alignment` 采集。
- **防抖口径**：连续 2 次失败才标红（AC6）；成功 1 次即恢复（偏保守显示，符合"尽快解除误报"）。
- **频率**：默认 60s（plan 可调档位：30s/60s/5min）；托盘隐藏态可降频或暂停。
- **范围**：本期只对域名地址做全链路探测；本机/局域网地址仅复用组件 probe 结果展示，不发起新探测。
- **聚合展示**：地址区域名行加状态点（绿=通/红=断/灰=未知），详情（分层结论+时间）展开可见。

## 5. 约束与假设

- 分层判定的聚合逻辑为纯函数（输入：DNS 结论 + probe 快照 + HTTPS 探测结果 → 分层结论），自动化测试；展示走手工验收清单（宪法 §1 窄例外）。
- 假设：单机自用场景，探测流量（≤1 次/分钟）对服务无压力。
- 依赖：004 的权威 DNS 检测与 probe 快照作为分层输入（只读复用）。

## 6. 开放问题

- [ ] 是否引入外部视角探测（check-host 类第三方 API 实测"真可达"）→ 需求方确认必要性（引入第三方依赖与延迟，换最真实的口径）。
- [ ] 检测频率档位与托盘降频策略 → plan 定。
- [ ] 是否覆盖本机/局域网地址的全链路探测 → plan 定（默认不做）。
- [ ] 红色标记是否需要伴随声音/托盘角标 → 需求方确认。
