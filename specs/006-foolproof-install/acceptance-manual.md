# 006-foolproof-install · 手工验收清单

> 宪法 §1 窄例外：纯 GUI 视觉/交互类 AC 以本清单为测试载体。真机验收时逐项勾选并记录。
> 验收环境：一台**新机/干净环境**（主流程）+ 现有生产机（回归抽查）。

## A. GUI 交互与视觉（§4.1）

- [ ] 主看板在装机未完成时显示引导条 + 「开始装机」；点击进入向导并定位基础阶段（AC1）
- [ ] 顶栏出现「装机向导」第三视图入口；中英双语随设置切换
- [ ] 向导左侧五阶段清单 + 四态 chip（待开始灰/完成绿/失败红/已跳过灰暗）（§4.1）
- [ ] 向导关闭重开后阶段状态原样恢复（wizard-state.json 持久化，AC2）
- [ ] 失败阶段红标 + 可读原因（稳定码转双语）+ 已完成阶段不受影响（AC12）

## B. 基础与腾讯云前置（AC3/4/5）

- [ ] 阶段①点「开始安装」弹 UAC 窗口跑 install-server.ps1；完成后点「我已完成，开始校验」→ 阶段变绿且主看板"局域网已可用"语义成立（同网段手机实测 http://<IP>:3001）
- [ ] 阶段②域名输入框保存后持久化（重开向导仍在）
- [ ] 「输入访问密钥」拉起 set-tencent-key.ps1：输入不回显、两次确认、复核仅显示 SecretId 末 4 位
- [ ] 故意输错密钥 → 校验显示"密钥无效"（auth_failed 文案）；换成正确密钥 → 校验通过
- [ ] 域名不存在于 DNSPod 时 → 校验显示"域名不存在"指引（domain_missing 文案）

## C. HTTPS 栈与直连（AC6/7/8）

- [ ] 阶段③点安装：install-https.ps1 拉起插件构建下载（显示"编译需数分钟"提示）；栈目录出现 caddy.exe/ddns-go.exe/插件式 Caddyfile（含 `dns tencentcloud {env.` 行）
- [ ] 启动后 443 出示 Let's Encrypt 有效证书（浏览器锁标；acme.sh 零参与）
- [ ] 阶段④选直连 → config-ddnsgo.ps1 生成 ddns-go.yaml（tencentcloud/url 模式）并拉起；权威 A 记录与出口一致 → 完成
- [ ] 603 蜂窝热点网络下直连校验显示 warn_private_range/warn_* 警示（不静默放行，AC8）
- [ ] 穿透分支下 ddns-go 未被配置/启动（通道互斥，AC9 后半）

## D. 穿透与收尾（AC9/10/11）

- [ ] 阶段④选穿透：set-frp-key 写密钥 → 填隧道 ID/节点域名保存 → frpc 自动拉起（004 守护），看板隧道"在线"
- [ ] DNS 自动对齐（004 sync），指引消失；未自动对齐时主界面通道卡显示手动 CNAME 指引
- [ ] 收尾页目标达成清单三行（局域网/域名状态点）；「注册开机自启」生效（任务计划程序可见）
- [ ] 「完成，回到主界面」→ done 持久化、主看板引导条消失

## E. 入口唯一化与旧机回归（AC13/14 + 非目标）

- [ ] 主看板运维工具区仅剩 4 项（升级 CloudCLI/客户端配置/重置 ddns-go 密码/ddns-go 管理页）
- [ ] CloudCLI 未安装时组件卡「去安装」跳转向导基础阶段（不直接拉脚本）
- [ ] **旧机回归**：生产机（acme.sh 证书链）重跑 install-https.ps1 → 既有 Caddyfile 原样保留、部署不受影响；向导/插件化零感知
