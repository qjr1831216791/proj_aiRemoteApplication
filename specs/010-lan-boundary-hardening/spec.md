## 1. 背景与问题

2026-09-12 全仓安全审查（三路并行探查：暴露面 / 组网模型 / Tauri 攻击面）结论：**局域网暴露是当前安全模型的最大弱点，且该弱点不依赖密钥泄露即可利用**。

1. **安全模型的根基与旁路**：007 §1 威胁模型成立的前提是「谁能触达 443/3001，谁就有一条拿到宿主机 shell 的路径」——上游 CloudCLI 零认证、自带 shell 终端、有未认证 RCE 前科（CVE-2026-31975，CVSS 9.8），且以宿主机管理员用户运行。007 以「零公网暴露 + 认证下沉网络层」收掉了公网面，但 008 把「局域网 IP 直访 `http://<ip>:3001`」保留为第一等方案：CloudCLI 监听 0.0.0.0 形态、零认证、明文 HTTP，唯一闸门是防火墙规则的 `-Profile Private`（本质是「网络归类」这个一比特开关）。
2. **闸门已实测失效一半**：007 acceptance-manual O1 实测记录 443 规则 Profile=Any（与 `enable-https.ps1` 声称的 Private 漂移）——若属实，公用网络下 443 照样放行，且 002 告警条件（规则 Profile 不含 Public）永不触发：用户在不可信 WiFi 上处于「以为有保护、实际 443 裸奔、且无提示」状态（待 plan 阶段真机复验）。
3. **攻击成本极低**：攻击者不需要「入侵局域网」，与宿主机同网段（咖啡店/酒店/公司访客 WiFi/被蹭网）即可打开 `http://<ip>:3001` 直达全权 Web IDE，全程不经过任何密钥。
4. **修复思路（需求方 2026-09-12 拍板）**：项目在 007 已建立网络层信任边界（EasyTier + network_secret，「不泄露密钥则无法入网」），本 Spec 把局域网边界**并入同一信任边界**——到达 CloudCLI/Caddy 的每一个入站包必须来自组网网段，未持密钥者在网络层不可达，使应用层零认证的事实不再构成攻击面。需求方原话定性：「像 EasyTier 那样，只要不暴露密钥就绝无被入侵的可能」。

方案取舍（需求方 2026-09-12 确认）：**默认收死局域网直访**（无凭证直访与「绝不」性质逻辑上不可兼得），例外访问降级为显式开关（用户决策 + 风险提示先行，002 哲学延续）。

## 2. 目标与非目标

### 目标（Goals）

- **443 入站改源网段白名单**：防火墙规则以「源地址 ∈ 组网虚拟网段」为唯一放行条件（Profile 可为 Any）——组网成员（异网/同 WiFi 均经 TUN 以虚拟 IP 到达）可访问；非成员设备（无论网络归类）TCP 握手不可建立。
- **3001 入站默认收死**：删除局域网直访放行规则，回落 Windows 默认拒绝；本机 loopback 访问不受影响（本机看板 + Caddy→3001 上游照常）。
- **例外开关「临时放行局域网」**：设置区提供显式开关，开启需风险提示确认（同网段任何设备可零认证直访 3001）；开启后同网段（专用网络）设备可直访 3001，关闭立即恢复不可达；默认关闭。
- **白名单随虚拟网段联动**：组网虚拟网段可编辑（009 交付），防火墙白名单必须随之同步刷新，二者永不漂移。
- **存量迁移**：真机旧规则（`CloudCLI LAN HTTPS 443` Private 语义 / `CloudCLI LAN 3001`）升级后不存在，新规则就位；装机脚本对新装机直接产出新规则。
- **看板与文案如实**：地址区「局域网」行如实反映收口态（默认不可直访、例外开启时显示可直访）；网络归类告警（002）与新规则契约适配。

### 非目标（Non-Goals · 本期明确不做）

- **不做应用层认证（basic_auth / mTLS / CloudCLI 自身认证）**：有爆破面或凭证分发成本，且不满足「网络层不可达」性质（2026-09-12 方案评审否决，理由见背景 4）。
- **不动 EasyTier 物理层监听（11010）**：P2P 打洞的物理层源 IP 不在虚拟网段，不能进白名单；11010 有 network_secret 认证，维持现状（`latency_first` 直连性能依赖）。
- **不动 Tauri 命令面硬化**（`run_tool` domain 参数注入、`mesh_apply_config` SHA256 校验短路、CSP=null）：安全审查的另一组发现，与本 Spec 的网络边界正交，另立 Spec。
- **不做 Caddy 二进制下载哈希锁定**：供应链补强另行安排。
- **不改公网侧任何语义**：A 记录=虚拟 IP、DNS-01 签发续期、域名访问形态均不变。

## 3. 用户故事与验收标准

### US1: 作为服务端用户，我希望未持组网密钥的设备在网络层无法触达我的服务，以便同网段设备不能借局域网入侵宿主机

- [ ] **AC1**: Given 组网在线、宿主机与若干非成员设备同网段 When 非成员设备探测宿主机局域网 IP 的 3001 与 443——含**将该设备自身物理网卡配置虚拟网段地址后以伪造源 IP 探测**（接口限定须拦截，见 §4 契约）Then 均不可达（连接超时/拒绝）；同场景下成员设备（异网）经 `https://ai.jackqi.cn/` 访问正常（外部探测与成员访问双通道实测，不采信宿主机本机探测——004/007 口径）。
- [ ] **AC2**: Given 组网在线 When 成员设备（与宿主机同一 WiFi，不换网）经 `https://ai.jackqi.cn/` 访问 Then 正常可达（源 IP 为成员虚拟 IP，命中白名单，与网络归类无关）。
- [ ] **AC3**: Given 任何网络环境 When 宿主机本机访问 `http://127.0.0.1:3001` 与工作台打开本机看板 Then 照常可用（loopback 不受白名单影响，Caddy→3001 上游照常）。
- [ ] **AC4**: Given 宿主机切换网络（WiFi ⇄ 热点）或当前网络被归类为公用 When 成员设备经域名访问 Then 可达性不受网络归类影响（443 规则 Profile 语义退役，白名单是唯一闸门）；002 网络归类告警不再因 443 触发误报/漏报。

### US2: 作为服务端用户，我希望在确有需要时能显式临时放行局域网直访，以便未装组网客户端的设备应急使用，且风险由我知情决策

- [ ] **AC5**: Given 设置区例外开关处于关闭（默认）When 查看地址区 Then 「局域网」行如实显示不可直访（引导经域名/组网访问）。
- [ ] **AC6**: Given 例外开关关闭 When 用户点击开启 Then 先展示风险说明（同网段任何设备可零认证直访看板=潜在宿主机 shell，仅限信任网络应急）并经 UAC 确认，批准后同网段（专用网络）设备可直访 `http://<ip>:3001`；关闭开关后立即恢复不可达；开关状态如实持久化并在看板常驻可见。
- [ ] **AC7**: Given UAC 被拒绝或规则操作失败 When 开关操作 Then 给出明确失败提示，程序不崩溃，放行状态保持原样。
- [ ] **AC8**: Given 例外开关处于开启且距开启已满 12 小时 When 自动回落时刻到达 Then 放行规则自动移除、开关回落为关闭并恢复不可达（需求方 2026-09-12 定：12h 自动关闭——正常连续工作不超过 12h，防误开后裸奔态永久）；回落结果在设置区如实可见。

### US3: 作为服务端用户，我希望白名单与组网配置永不漂移，以便改网段后成员访问不中断、外人进不来

- [ ] **AC9**: Given 用户在设置区修改组网虚拟网段并保存 When 配置生效 Then 防火墙白名单同步刷新为新网段，成员（新网段虚拟 IP）访问正常、旧网段源不再放行；网段非法/与物理网卡冲突被 009 既有检测阻断时白名单不变。

### US4: 作为维护者，我希望升级与新建机两条路径都收敛到新规则契约，以便不再有 Private 语义的旧规则残留

- [ ] **AC10**: Given 真机存量旧规则（`CloudCLI LAN HTTPS 443`/`CloudCLI LAN 3001`，Private 语义）When 升级到本版本并执行相应入口 Then 旧规则被移除并以新契约重建（升级迁移）；新装机路径（装机向导/脚本）直接产出新契约规则；全仓检索无「以网络归类放行 443/3001」的残留创建逻辑（008 全仓盘点口径）。

## 4. 功能需求与边界

- **新规则契约**：443 规则 = 入站 TCP 443 + **源地址 ∈ 组网虚拟网段**（默认 `10.126.126.0/24`，随设置联动）+ **接口 = EasyTier TUN 虚拟网卡**（双条件 AND）+ Profile Any。双条件的必要性：仅「源网段」单条件可被同网段设备将网段地址 alias 到自身物理网卡绕过——该场景下回包可送达、握手可完成，不构成盲欺骗；接口限定使伪造包从物理网卡进入即不匹配，而 TUN 只有持密钥入网的 EasyTier 可写入。规则名作为程序内契约（002 先例）需唯一且稳定，TUN 接口标识的稳定绑定形态 plan 定。3001 默认无放行规则（例外开关开启时的 3001 放行面向物理局域网，不叠加 TUN 接口条件）。
- **例外开关实现形态**：开启 = 以最小暴露面重建 3001 放行（默认仅专用网络，与 sprint0 语义一致）；关闭 = 移除；**开启满 12 小时自动回落关闭**（需求方 2026-09-12 定，防误开后裸奔态永久——回落不依赖应用常驻在 plan 定，应用退出期间到期则在下次启动时补回落）。开关仅影响 3001，不提供 443 的局域网放行（443 永远只走白名单）。
- **002 适配边界**：`network.rs` 对防火墙规则的检测契约随新规则同步（检测什么、告警文案是否保留，plan 定）；例外开启期间网络归类对 3001 的作用如实呈现（专用才可达）。
- **收口判定口径**：非成员不可达的验证一律用独立设备外部探测（004 教训：不采信宿主机本机探测）；本机视角仅验证 loopback 可用性。
- **失败语义**：防火墙规则创建/删除失败不得中断组网服务运行（规则操作与组网服务解耦），失败如实上报看板/提示。
- **域名与组网在线的边界**：白名单放行的是「源 IP ∈ 虚拟网段」，与组网服务是否在线解耦——服务停止时成员自然不可达（无 TUN 路由），但规则保持，服务恢复即恢复可达，无需重建规则。

## 5. 约束与假设

- **真机实测是验收前提**（007 先例）：AC1 的「非成员不可达」必须经独立设备在真实局域网实测；443 旧规则 Profile=Any 漂移在 plan 阶段先复验留档。
- 使用者假设沿 002/007：管理员账户、UAC 可弹；例外开关与迁移涉及防火墙规则操作，需提权路径。
- 组网成员经 TUN 到达宿主机时源 IP 恒为成员虚拟 IP（overlay L3 语义；007 真机成员列表已有虚拟 IP 佐证，plan 阶段以防火墙日志/抓包复核）。
- 脚本改动须同步双份（`resources/bin` 与 `tools/sprint0/bin`）并登记 `build.ps1 $ScriptSubset`/manifest——006/008 打包漂移教训。
- 判定逻辑（白名单网段 × 设置网段一致性、例外开关状态 × 规则存在性）为纯函数自动化测试；GUI 呈现走手工验收清单（宪法 §1 窄例外）。
- 本 Spec 属安全补强，行为变更（局域网直访默认退役）用户可感知，发布记入 CHANGELOG 并按 SemVer 升 minor（0.x 阶段）。

## 6. 开放问题

- [x] 真机 443 旧规则 Profile 实际值复验（Any 漂移留档）→ **已决（T1 复核 2026-09-12）**：`CloudCLI LAN HTTPS 443` 与 `CloudCLI LAN 3001` 实测均 Profile=Private、RemoteAddress=Any、InterfaceAlias=Any——007 acceptance-manual O1 记录的 443 Profile=Any 漂移在当前真机**不可复现**（推测规则在其后被重装流程重建）；留档 plan §1 取证与 §7-R2，漂移风险类别随 Profile 语义退役而消亡。
- [x] 002 告警逻辑的去留形态（整体退役 vs 改写为白名单健康检查）→ **已决（plan §3.6）**：443 归类告警整体退役（needs_alert/告警条/规则探测段删除），网络归类**调整**入口（002 US2）保留；「公用网络下例外不生效」改为白名单健康区的 `public_blocks_exception` 提示位。
- [x] 升级迁移的触发时机（应用启动自检 vs 随装机脚本/向导）→ **已决（plan §3.7）**：应用启动自检（只读 status）发现旧规则 → 看板横幅「一键收口」显式迁移（幂等：删两条旧规则 → ensure-whitelist），向导收尾页同入口；装机脚本对新装机直接产出新契约或不再创建规则。
- [x] 例外开关是否需要自动超时 → **12h 自动回落关闭**（需求方 2026-09-12 定：正常连续工作不超过 12h；初稿设想的 24h 被需求方中途改为 12h）。
- [x] TUN 虚拟网卡接口名的稳定性与规则绑定形态（InterfaceAlias vs 接口 GUID；服务重装、驱动升级后是否恒定）→ **已决（T1 实测 2026-09-12 + plan §3.3）**：接口名 `et_8_1999` 为 wintun 按实例生成（`et_*` 后缀随实例变，服务重装/驱动升级不保证复用），**不可作契约常量**；规则绑定走运行期解析——以「持有 virtual_ip 的 IPv4 适配器」为语义锚点解析 InterfaceAlias（本机实测：ifIndex 60、InterfaceType 53、虚拟 IP 10.126.126.1/24 单一 IPv4 挂载）。
- [ ] 分发场景边界：多台工作台主机加入**同一**网络时的虚拟 IP 规划（当前各机均写死 `.1`，同网络必冲突）与默认网络名 `ai-remote` 撞名（密钥不同则不互通、仅握手噪音，但易混淆）→ 需求方确认纳入本期或另立 Spec。
