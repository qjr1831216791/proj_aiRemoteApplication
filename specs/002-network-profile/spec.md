## 1. 背景与问题

HTTPS 部署形态（`https://ai.jackqi.cn`）依赖防火墙入站规则「CloudCLI LAN HTTPS 443」放行 TCP 443，该规则**仅对"专用"网络配置文件生效**（sprint0 `enable-https.ps1` 的安全设计：创建规则时只放行 Private，并把当时的非域网络一律改为专用）。

试用反馈（2026-09-09，问题 4）暴露的断链：用户换到新网络（如公司访客 WiFi、手机热点）后，Windows 将其默认归类为**"公用"**，443 规则不生效 → 本机自测正常、其他设备（手机）访问域名被静默拦截。用户不知情、无处排查，也没有便捷的调整渠道（`enable-https.ps1` 能改，但它是装机入口且每次换网都要手动想起重跑）。

需求方明确（2026-09-09）：**防火墙拦截本身可接受，但 APP 要有反馈，且要提供由用户决策的调整渠道——APP 只需在提示中讲清风险。**

## 2. 目标与非目标

### 目标（Goals）

- 桌面程序检测"443 规则存在但当前网络归类导致其不生效"的状态，并在主界面**显式提示**（何时提示、何时消失，见 AC）。
- 提供**用户显式决策**的网络归类调整入口：把选中的活动网络在 公用 ⇄ 专用 间切换（需管理员/UAC），切换前展示风险说明。
- 切换结果可视化：成功后状态提示随轮询自动刷新；失败（UAC 拒绝/命令失败）给出明确提示且不崩溃。

### 非目标（Non-Goals · 本期明确不做）

- **不自动修改网络归类**：一切调整必须用户显式点击并经确认（需求方原话："由我来决策"）。
- **不增删改防火墙规则本身**：规则的存在与内容仍由 `enable-https.ps1` / `install-https.ps1` 负责；规则不存在（HTTPS 栈未配置）时本程序不提示、不代劳（属装机流程）。
- **不做网络可达性诊断**：AP 隔离、DNS 解析、证书有效性等"改了归类仍可能不通"的因素不在检测范围；提示文案如实使用"可能无法访问"措辞，不承诺诊断结论。
- **不做非活动网络（记忆网络）的管理**：只处理当前活动连接（`Get-NetConnectionProfile` 返回集）。
- 不新增客户端/手机侧能力。

## 3. 用户故事与验收标准

### US1: 作为服务端用户，我希望程序在我换到被拦截的网络时主动告知，以便域名访问失效时不必盲猜原因。

- [ ] **AC1**: Given 存在防火墙规则「CloudCLI LAN HTTPS 443」且其 Profile 不含 Public，且当前至少有一条活动网络归类为 Public When 主界面打开 Then 显示网络提示，文案含三要素：当前网络名、归类为"公用"、对域名访问的后果（"其他设备可能无法通过域名访问"）；提示不阻塞任何其他功能。
- [ ] **AC2**: Given 所有活动网络均为专用（或规则 Profile 已含 Public，或规则不存在） When 主界面打开 Then 不显示该提示。
- [ ] **AC3**: Given 提示已显示 When 用户经本程序或其他手段把网络改为专用（或网络切换） Then 提示在轮询周期内自动消失（前台 ≤30s），无需重启程序。
- [ ] **AC4**: Given 网络状态查询失败或无活动网络 When 判定 Then 静默不提示、不报错（降级不劣化现有体验）。

### US2: 作为服务端用户，我希望在程序内把当前网络改为专用（或改回公用），以便无需回命令行且由我自己权衡风险。

- [ ] **AC5**: Given 网络提示存在（或用户主动展开网络区） When 点击某条活动网络的「设为专用」 Then 先展示风险说明（专用网络下本机在局域网内更易被发现，请仅在信任的网络如个人热点/家庭网络这样做）并要求确认，确认后弹 UAC；批准且执行成功后该网络状态刷新为专用、提示消失。
- [ ] **AC6**: Given 用户想把已设为专用的网络改回公用 When 点击「设为公用」 Then 等价执行（无需 UAC 时自然跳过，仍需 UAC 时弹窗），成功后状态刷新；文案说明这是"减少局域网暴露面"的方向。
- [ ] **AC7**: Given UAC 被拒绝或修改命令非零退出 When 执行 Then 给出明确失败提示（含可能原因），程序不崩溃，网络状态保持原样。
- [ ] **AC8**: Given 多条活动网络并存 When 展示与操作 Then 逐条显示网络名与归类，操作按钮按条独立、互不影响。

## 4. 功能需求与边界

- **判定口径**：提示条件 = 「规则存在 ∧ 规则 Profile 集合不含 Public ∧ ∃活动网络归类 Public」。归类值映射：0=公用、1=专用、2=域（域网络视为不受该规则约束，不触发提示）。
- **刷新时机**：随主界面打开加载一次 + 前台周期轮询（间隔 plan 定，建议 ≤30s；与现有状态轮询独立，避免耦合）。托盘态（主窗隐藏）可暂停或降频。
- **修改通道**：与 spec 001 低频操作同款语义——UAC 提权执行网络归类修改（程序内等效实现，不依赖 sprint0 脚本；具体用 PowerShell `Set-NetConnectionProfile` 还是原生 API 由 plan 定）；以退出码映射成功/失败（AC20 模式）。
- **风险提示必须先于执行**：确认框中完整展示切换方向的影响；「设为专用」额外强调仅在信任网络操作。
- **边界**：修改针对指定 `InterfaceIndex`，不批量操作全部网络；执行期间按钮防重复点击；网络在执行瞬间切换导致目标失效时按失败处理并提示。

## 5. 约束与假设

- 归类查询为非特权操作；修改需管理员（UAC 可弹，假设延续 spec 001：使用者是管理员账户）。
- 程序不持久化网络相关设置（这是环境操作，不是行为开关）。
- 提示文案中英双语（AC25 同款语言机制）；风险文案为合规性内容，不得弱化。
- 判定逻辑（规则 Profile × 活动网络归类 → 提示与否）为纯函数，须自动化测试；命令构造（InterfaceIndex/NetworkCategory 参数、提权、`-Lang`）单测覆盖；GUI 展示与交互走手工验收清单（宪法 §1 窄例外）。
- 假设：防火墙规则名「CloudCLI LAN HTTPS 443」保持 sprint0 契约不变。
