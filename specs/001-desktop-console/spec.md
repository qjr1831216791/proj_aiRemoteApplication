## 1. 背景与问题

Sprint 0（v0.1.0）用 `tools/sprint0/start-here.bat` 的数字菜单管理 CloudCLI + Caddy + ddns-go 三组件，全部能力已脚本化且经实战验证。痛点：

1. **日常操作路径长**：每次启停服务都要开黑窗、输菜单数字；状态不可一览。
2. **操作入口分散**：启停（菜单 1/2）、自启开关（菜单 7/8，独立脚本）、排障入口各自为政，没有统一状态视图。
3. **观感与心智**：控制台菜单与"清爽的桌面工具"预期有差距。

Sprint 1 交付一个 **Windows 桌面程序（AI 远程工作台桌面版）**：sprint0 全部能力的 GUI 化，并作为三组件的**统一控制面**。对齐 [产品愿景](../../docs/product.md) 路线图 Sprint 0 → M0 之间的体验补强。

**架构总纲（v2，经三方评审确定）**——控制面/数据面分离（Tailscale / Docker Desktop 同款模式）：

```
三组件（数据面）            桌面程序（控制面）
CloudCLI/Caddy/ddns-go  ←─  状态监测 / 一键启停 / 自启托管 / 低频操作入口
经登录计划任务常驻，           程序退出/崩溃不影响服务运行；
独立于程序存活                「停止服务并退出」为显式收摊操作
```

**已确认的关键决策**（2026-09-08，与需求方澄清；★ 为 v2 评审后修订）：

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 技术栈 | Tauri 2（Rust + WebView2 + Web 前端）；.NET 8 WPF 为 Plan B（切换判据见 §5） |
| 2 | 密钥可视化 | **不做**密钥/KeyId 编辑（凭证由 ddns-go 管理页维护，程序仅提供直达入口）；只做应用自身设置。sprint0 新增的 `install-https` 亦将密钥两步刻意留手工（"涉及密钥，刻意不自动化"），与本决策互证 |
| 3★ | 退出语义 | **默认退出保留服务**；托盘提供显式「停止服务并退出」一键收摊；设置可反转为"退出即停止"。（v1 曾定为"默认停止全部"，评审指出 GUI 单点故障风险后反转，见变更记录） |
| 4★ | 服务自启体系 | 三组件继续经**登录计划任务**常驻（程序托管开关，等价菜单 7/8）；程序自启为独立开关；程序**不用**注册表 Run 键（有被安全软件静默禁用的实证风险） |
| 5★ | GUI 类 AC 测试 | [宪法](../../docs/constitution.md) §1 增窄例外：纯 GUI 视觉/交互类 AC 可手工验收清单覆盖，逻辑类 AC 仍须自动化 |
| 6★ | 端口/路径设置 | 本期**只读展示**（改端口/路径须重跑 `install-server.ps1 -Port` 联动防火墙与 Caddyfile，程序内改只会造成"表面生效、实际全断"） |
| 7 | 联动语义 | 「程序启动时联动补齐未运行的服务」默认开启，**同时适用于自启与手动启动**（对应诉求"启动程序=触发能力"）；可关闭 |

## 2. 目标与非目标

### 目标（Goals）

- 桌面程序承载 sprint0 总控菜单（1~9）的**全部能力**（含 v1 遗漏的菜单 7/8：服务自启开关），以及菜单外的 bin 级装机入口 `install-https`（sprint0 于 2026-09-08 新增），等价或更好。
- 一个"启动/停止"总开关管理三组件（等价菜单 1/2），状态实时可视化，组件级可单独重试。
- 自启体系可视化：服务自启（托管三条登录计划任务）与程序自启两个独立开关；程序自启时可联动补齐服务，也可只启动程序。
- 退出语义遵循决策 3：默认保留服务，显式收摊一键停全部。
- 轻量：安装包 ≤ 15MB；常驻内存（程序 + WebView2 子进程合计、启动 5 分钟后测量）目标 ≤ 150MB；蓝白清爽 UI。
- **易于打包与分发**：一条命令产出**双形态产物**——离线可装的 NSIS 安装器（embedBootstrapper）+ 便携 zip（exe + 资源目录，解压即用）；产物自包含、命名含版本号，可直接经聊天工具 / 网盘 / GitHub Release 分发。

### 非目标（Non-Goals · 本期明确不做）

- **不做密钥/KeyId 编辑器**：腾讯云密钥实际存于 `ddns-go.yaml`（经其网页管理页维护），`.env` 中的登记从未被脚本消费；程序内重复造编辑器有写坏配置的风险、无收益。未来自研组件需要 `.env` 管理时另立 Spec。
- **不重写 sprint0 脚本的对外行为**：程序复用脚本清单见 §4.1；Caddy/ddns-go 的启停守卫逻辑原为 `menu.ps1` 内联代码，本期在程序内**等效移植**（不改脚本、不新增脚本）。
- **端口/路径不可编辑**（决策 6）：换端口/换目录的正道是带参重跑安装脚本，程序提供只读展示与指引。
- **不做客户端（其他电脑/手机）版本**：程序仅在服务端（跑 AI 的开发机）运行；客户端继续用浏览器 + `install-client`。
- **不做公网中转、多用户、鉴权增强**：沿用 sprint0 的局域网 + 域名 HTTPS 模式。
- **不做 macOS / Linux 版**；**不做程序自动更新**（自用阶段风险大于收益，后期可叠加官方 updater）。

## 3. 用户故事与验收标准

### US1: 作为服务端用户，我希望在桌面程序里一眼看到三组件状态并一键启停，以便不依赖黑窗菜单。

- [ ] **AC1**: Given 三组件均未运行 When 点击「启动」 Then 程序补齐启动 CloudCLI(3001) / Caddy(443) / ddns-go(9876)，状态进入"启动中"并轮询至就绪（典型环境 ≤30s；60s 未就绪判失败，展示 `%TEMP%\cloudcli.log` 尾部与失败原因；脚本 exit 1 映射为"CloudCLI 未安装/不可用"提示），就绪后显示各端访问地址（本机 / 局域网 IP / https://ai.jackqi.cn）。
- [ ] **AC2**: Given 三组件运行中 When 点击「停止」 Then 逐组件执行停止（含进程树清理与端口复核），端口 3001/443/9876 均释放，状态转为"未运行"；单组件停止超时 10s，超时记日志并给出手动排查命令，不阻塞其余组件的停止。
- [ ] **AC3**: Given 部分组件已在运行 When 点击「启动」 Then 仅补齐缺失组件，不产生重复进程（幂等，等价现有端口守卫行为）。
- [ ] **AC4**: Given 主界面打开 When 任一组件被外部手段停止（如任务管理器） Then 10s 内该组件状态自动转为"未运行"（界面打开时轮询间隔 ≤5s，无需手动刷新）。
- [ ] **AC5**: Given 服务由外部通道启动（start-server.bat / 计划任务） When 程序启动 Then 状态如实显示"运行中"，且「停止」可正常接管停止。
- [ ] **AC6**: Given 点击「启动」后某组件启动失败（如 Caddy 443 被占） When 其余组件启动成功 Then 成功组件显示"运行中"、失败组件标红并给出错误原因，且提供「重试该组件」操作；总开关不显示笼统的"启动成功"。
- [ ] **AC7**: Given 某组件端口被**非本组件**进程占用 When 程序探测状态 Then 显示独立的"端口被占（进程名 X）"状态（告警色），不显示"运行中"；判活为"端口 Listen + 监听进程身份匹配"双口径。

### US2: 作为服务端用户，我希望自启体系在程序内可视化托管，以便重启后无需人工干预即恢复远程工作台。

- [ ] **AC8**: Given 设置「服务开机自启」开启（默认） When 程序注册自启 Then 三条登录计划任务（`* Sprint0 autostart`）被幂等注册/重建（行为等价 `setup-autostart.ps1` 重跑）；若任务已存在则**接管**而非报错，不产生双通道。
- [ ] **AC9**: Given 「服务开机自启」关闭 When 执行关闭 Then 三条计划任务被移除（等价 `setup-autostart.ps1 -Remove`），正在运行的进程不受影响。
- [ ] **AC10**: Given 「程序开机自启」开启（默认关） When 重新登录 Windows Then 程序自动启动并常驻托盘，不弹出主窗口。
- [ ] **AC11**: Given 「程序开机自启」+「启动时联动补齐服务」均开启 When 登录 Then 程序自动执行与 AC1/AC3 等价的补齐启动；联动关闭时仅启动程序、不拉起服务。服务自启与程序自启同时开启时，双通道靠幂等守卫兼容（重复拉起为无害空操作）。
- [ ] **AC12**: Given 手动双击启动程序 When 「联动补齐」开启 Then 同样执行补齐启动（决策 7）；关闭则仅展示状态。

### US3: 作为服务端用户，我希望退出行为可控且不影响远程可达性，以便手机端不因本地误操作断线。

- [ ] **AC13**: Given 默认设置 When 通过托盘「退出」退出程序 Then 三组件继续运行（远程访问不受影响）。
- [ ] **AC14**: Given 用户选择托盘「停止服务并退出」 When 执行 Then 先完成与 AC2 等价的停止（收摊总超时 30s，超时记日志后放行退出），再退出程序。
- [ ] **AC15**: Given 设置中"退出行为"改为"退出即停止" When 普通退出 Then 等价 AC14。
- [ ] **AC16**: Given 程序崩溃或被强杀 When 三组件在运行 Then 服务不受影响；再次启动程序可正常接管管理（服务不挂在程序的 kill-on-close Job 里）。
- [ ] **AC17**: Given Windows 注销/关机 When 系统发起会话结束 Then 程序不做收摊动作（会话内用户级进程由系统统一终止，收摊无意义且 5s 窗口内不可靠）。
- [ ] **AC18**: Given 关闭主窗口（X） When 未选择退出 Then 程序最小化到托盘继续运行。

### US4: 作为服务端用户，我希望低频管理操作在程序内一键可达，以便装机与排障不回命令行。

- [ ] **AC19**: 程序提供与总控菜单等价的入口：查看各端访问地址（菜单 3）、安装/重装服务端（菜单 4，UAC）、升级 CloudCLI（菜单 4 变体，`-Update`）、HTTPS 环境配置（菜单 5，UAC）、HTTPS 栈装机（`install-https`，UAC **可见窗口**——其结尾打印的"两步手工活"命令与踩坑警告必须完整可读）、客户端配置（菜单 6，**可见窗口**执行——该脚本为交互式）、打开 ddns-go 管理页（菜单 9）、打开本机工作台页面。
- [ ] **AC20**: Given 点击需管理员的操作 When UAC 弹窗被拒绝或脚本执行失败（非零 exit） Then 程序给出明确提示且不崩溃。

### US5: 作为用户，我希望设置可视化并持久化，以便调整行为不改文件。

- [ ] **AC21**: 行为开关类设置——服务开机自启（默认开）、程序开机自启（默认关）、启动时联动补齐服务（默认开）、退出行为（默认"保留服务"，可选"停止服务"）、启动后自动打开工作台页面（默认关）——保存后立即生效，重启程序后保持。
- [ ] **AC22**: 组件端口与路径**只读展示**（默认 3001 / 443 / 9876、`D:\Software\cloudcli-https`，支持一键复制，附"修改须重跑安装脚本"指引）。
- [ ] **AC23**: Given 首次运行无设置文件 When 程序启动 Then 全部使用默认值并可正常使用全部功能。
- [ ] **AC24**: Given 设置文件损坏（非法 JSON/半写入） When 程序启动 Then 回退全部默认值、给出提示、不崩溃，损坏文件改名留档（`.bak`）。
- [ ] **AC25**: Given 首次运行（语言默认"跟随系统"） When 系统**显示语言**为中文 Then 程序全部文案——界面、托盘菜单等原生文案、脚本 `-Lang`——均为中文，否则均为英文；用户可切换 跟随系统 / 中文 / 英文，切换**立即生效**（含托盘菜单重建，无需重启程序）；显式选择持久化并**优先于**系统语言；程序调用脚本时显式传 `-Lang` 与当前生效语言对齐。

## 4. 功能需求与边界

### 4.1 脚本复用清单（v2 新增，澄清"编排壳"边界）

| 能力 | 实现方式 |
|------|----------|
| CloudCLI 启动 | 复用 `run-server-hidden.ps1`（隐藏执行，消费 exit code） |
| CloudCLI 停止 | `stop-server.ps1` 语义的**程序内等效实现**（定位监听进程 → 进程树结束 → 端口复核）；脚本本身保留为命令行兜底入口（树杀须先收集进程树再动手，故不直接复用脚本，见 §4.4） |
| Caddy / ddns-go 启停与守卫 | `menu.ps1` 内联逻辑的**程序内等效移植**（端口守卫 + 提权不需要） |
| 服务自启托管 | 复用/对齐 `setup-autostart.ps1` 的任务名与参数（幂等重建语义） |
| 安装/升级/HTTPS/客户端配置 | 拉起 `install-server.ps1`（可带 `-Update`/`-UseMirror`）、`install-https.ps1`（UAC 可见窗口，结尾手工步骤提示须完整可读）、`enable-https.ps1`（UAC 可见窗口）、`install-client.ps1`（**非 UAC 但交互式，可见窗口**） |
| 状态探测 | 程序内实现：端口 Listen + 监听进程身份双口径 |

### 4.2 正常流程

1. 首次运行：默认设置（AC23）→ 主窗口展示三组件状态与总开关。
2. 日常：**托盘常驻是程序固有形态**——无论手动启动还是自启，托盘图标始终存在（自启经 `--hidden` 参数静默入托盘，AC10）；主窗口只是视图，关闭（X）即最小化回托盘（AC18），不退出进程；托盘菜单：启动 / 停止 / 打开工作台页面 / 显示主界面 / 停止服务并退出 / 退出。
3. 登录（自启开启时）：服务由计划任务拉起；程序（若开启自启）静默启动并按联动设置补齐服务。
4. 状态探测以端口监听 + 进程身份为准，与 sprint0 脚本同一判定口径。

### 4.3 脚本调用约定

- 非交互脚本：隐藏窗口执行（`CREATE_NO_WINDOW`，非 `-WindowStyle Hidden`）、`-NoProfile -NonInteractive`、显式管道 stdio、带超时；stdout/stderr 写入程序日志文件（设置页可打开目录）。
- 交互式脚本（`install-client.ps1`）：拉起可见控制台窗口执行。
- 提权脚本（install/enable-https）：`ShellExecuteW` verb `runas` 拉起，UAC 由系统弹窗；提权子进程输出不回流管道，结果以退出码/日志文件为准。
- 所有调用显式传 `-Lang` 与程序语言一致；exit code 映射到 UI 状态与提示。

### 4.4 停止路径与进程树

- 停止顺序与兜底：`stop-server.ps1`（3001）→ `caddy stop`（超时 5s；失败则按 443 端口找监听进程、校验可执行路径为 StackDir 下的 caddy.exe 后强杀）→ ddns-go **按可执行路径匹配**（非进程名）强杀 → 复核端口释放。
- CloudCLI 为宿主进程、派生 claude 会话子进程：停止按**进程树**结束（避免"UI 显示已停、claude 会话仍在跑"的计费/写文件风险）；UI 文案明确"停止会结束进行中的 AI 会话"。
- 「启动中」为独立状态：停止/收摊操作先等待或取消在途启动，再判定端口（消除"退出后组件姗姗来迟自己起来"的竞态）。

### 4.5 边界与异常

- **单实例**：跨会话唯一（`Global\` 命名空间互斥体）；重复启动激活已有实例。
- **多会话**：程序仅管理当前用户会话内的组件进程；跨会话操作（如 RDP 会话退出收摊影响本机会话）给明确提示而非静默执行。
- **脚本缺失**：引用的 sprint0 脚本不存在时，相关按钮禁用并提示定位方式，不崩溃（分发策略见开放问题）。
- **退出收摊失败**：记日志 + 手动排查命令提示，超时放行退出。
- **WebView2 缺失**：安装器默认引导（Win10 1803+/Win11 预装，覆盖目标环境）。

### 4.6 UI 基调

- 蓝白清爽：白底/浅灰卡片 + 蓝色主操作色；状态色：绿（运行中）/ 灰（未运行)/ 蓝（启动中）/ 橙红（失败或端口被占）。
- 主界面信息分区：状态卡（三组件 + 总开关 + 组件级重试）、访问地址区、低频操作区（折叠或次级页）。
- 窗口 `visible: false` 创建、页面就绪后显示（规避 WebView2 首帧白屏）。

## 5. 约束与假设

- **技术栈**：Tauri 2 + WebView2 + Rust；选型经专项评审（结论"成立但有条件"，2026-09-08）。Plan B：.NET 8 WPF，**切换判据**：Rust 侧进程管理（Win32 调用）两周内无法推进即切换，UI 层可平移。
- **体积/性能**：安装包 ≤ 15MB（同类实测 8.6MiB）；常驻内存（程序 + WebView2 子进程合计，启动 5 分钟后）目标 ≤ 150MB，**里程碑 1 骨架实测**后决定是否收紧；前端保持轻依赖，不引入重型 UI 框架。
- **分发**：未签名分发存在 SmartScreen/Defender 误报可能——定位自用可接受，安装文档写明"仍要运行"引导；公开分发再议签名（不属本期）。
- **打包分发**（2026-09-08 需求方补充）：构建一键化（`scripts/build.ps1`：同步脚本副本 → 校验版本对齐 → 构建 → 双形态产物）；安装器用 embedBootstrapper（+1.8MB，目标机**离线也能装**）；便携包目录结构与安装版一致；产物不含密钥与 `.env`；覆盖安装可升级且设置保留。
- **自启通道**：程序与服务自启一律走登录计划任务（`ExecutionTimeLimit Zero`，支持延迟触发），**不用**注册表 Run 键。
- **服务与程序解耦**：三组件不挂入程序的 kill-on-close Job Object；程序退出/崩溃不带走服务（AC16 的实现前提）。
- **脚本契约不变**：不修改 `tools/sprint0/bin/` 各脚本对外行为；如确需小改，保持向后兼容并在提交中说明。
- **安全**：设置文件不含密钥；程序不读写 `.env`；日志不记录敏感数据（宪法 §3）。
- **测试**（对齐宪法 §1 窄例外）：逻辑类 AC 自动化覆盖——设置存取/默认值/损坏恢复（AC21/23/24）、语言 auto 判定纯函数（AC25）、状态双口径判定（AC5/7）、命令编排参数与 `-Lang`/exit code 映射、自启任务注册/移除/接管的参数正确性（AC8/9）；GUI 交互类 AC（AC1/2/4/6/10-14/18-20 等）以 tasks.md 中的**手工验收清单**覆盖。
- **假设**：使用者为管理员账户（UAC 可弹）；三组件端口守卫幂等假设成立（sprint0 已验证）；开发机为 Win11；`ai.jackqi.cn` 与 `D:\Software\cloudcli-https` 为**当前部署实例默认值**而非产品常量。
